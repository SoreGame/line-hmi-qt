# JSON-сообщения пульта line-hmi-qt в NATS

Собрано по коду: `src/NatsClient.cpp` и места вызова в `LineController.cpp`, `AdminPanel.cpp`,
`ZonesDialog.cpp`.

Когда запускать и останавливать скрипты, решает ПЛК (см. [PLC_PROTOCOL.md](PLC_PROTOCOL.md)
и [LOGIC.md](LOGIC.md)). Пульт только исполняет эти решения в NATS.

Адрес сервера — `server.ip:server.port` из `config.json` (сейчас `192.168.11.170:4222`).
Таймаут подключения 5 с, при обрыве пульт переподключается каждые 3 с.
Все сообщения — компактный JSON в UTF-8. Ответов (request/reply) пульт не ждёт: только publish,
subscribe и чтение/запись KV.

## 1. Что пульт отправляет (publish)

### 1.1. Запуск скрипта — `script.command`

```json
{
  "command": "exec",
  "type": "Script",
  "code": "<текст скрипта .chai>",
  "from_line": 1,
  "filename": "<имя скрипта>",
  "slot": "motion"
}
```

- `code` пульт сначала читает из KV (см. раздел 3.1) и вставляет целиком.
- `from_line` всегда 1.
- `filename` — то же имя, по которому скрипт лежит в KV. По нему пульт потом узнаёт свой скрипт
  в `script.status`.
- `slot`: `"motion"` (цикл / preProg) или `"search"` (долгоживущий скрипт камеры). Без поля behaviour считает `motion`.
- Формат совпадает с `executeScript()` веб-редактора (там тоже можно выбрать слот).

Когда отправляется:

| Ситуация | Какой скрипт (поле в админке) | slot |
|---|---|---|
| ПЛК изменил ячейку 60 (разрешение init) | init-скрипт детали + **параллельно** скрипт камеры (`Камера · Деталь 1/2`) | motion + search |
| ПЛК закончил предподготовку (ячейка 56: 0 → 1 в режиме 3 «в работе») | через 5 с — основной скрипт детали из ячейки 54 (`Основная · Деталь 1/2`) | motion |
| Основной скрипт дошёл до конца, по свежему кадру ПЛК в режиме 3 и 56 = 1 | тот же основной скрипт заново | motion |

Пока идёт **motion**-скрипт, запущенный пультом, второй motion-`exec` пульт не шлёт. Слот `search` живёт отдельно и не занимает эту блокировку. В `script.status` есть поле `slot`; статусы `search` не завершают init/main.

### 1.2. Полный стоп — три сообщения подряд

Одно и то же сообщение уходит в три subject по порядку:

| Subject | Payload |
|---|---|
| `motion.command` | `{"command": "stop"}` |
| `behaviour.command` | `{"command": "stop"}` |
| `script.command` | `{"command": "stop"}` |

Останавливаются и движение, и скрипт. Иначе следующий `delay()`/`moveL` в скрипте снова включил бы
движение на контроллере. Так же делает `stop()` в `robot-gui`.

Когда отправляется:
- ПЛК перешёл в «остановку» (ячейка 52 = 2), пока идёт init-скрипт;
- в «остановке» основной цикл не закончился за таймаут стопа из админки;
- 3 с нет кадра от ПЛК (сторожок пульта).

При аварии робота в NATS останавливает ПЛК, пульт этого не делает.

### 1.3. Скорость движения скриптов — `behaviour.command`

```json
{"command": "setMotionSpeed", "percent": 100}
```

`percent` — 5…110. Behaviour умножает длительность каждого `moveL` / `moveB` / `moveOffset`
на `100 / percent` (110% → быстрее, 5% → медленнее). `delay()` не меняется.
Пишется из окна «Сервис» и при подключении пульта к NATS (значение из
`system.motionSpeedPercent` в config.json).

### 1.4. Выключить приводы — `motion.command`

```json
{"command": "stop"}
```

Только в `motion.command`, скрипт не останавливается.

Когда отправляется: кнопка включения/выключения приводов в админке, если приводы были включены.

### 1.5. Включить приводы — `motion.command`

```json
{"command": "start"}
```

Когда отправляется: кнопка включения/выключения приводов в админке, если приводы были выключены.

### 1.6. Сдвиг робота — `motion.command`

```json
{
  "command": "moveOffset",
  "duration": 1,
  "offset": {"x": 0.0, "y": 0.0, "z": 0.0, "r": 0.0}
}
```

- `offset` — сдвиг от текущей позиции на выбранный в админке шаг; меняется одна ось за нажатие.
- `duration` всегда 1.

Когда отправляется: кнопки ручного перемещения в админке, только при включённых приводах.

## 2. Что пульт слушает (subscribe)

Подписки создаются сразу после подключения.

### 2.1. `motion.status` — от CTRL

Пульт читает:

```json
{
  "pose": {"x": 0.0, "y": 0.0, "z": 0.0, "r": 0.0},
  "run": true
}
```

- Любое сообщение здесь — heartbeat CTRL. Если последнее было больше 2 с назад, CTRL считается
  отключённым: в опросе ПЛК `f2 = 0`.
- По `pose` пульт определяет стартовую зону робота и шлёт её номер ПЛК в байте `Z` опроса.
  Поза старше 2 с не учитывается (`Z = 0`).
- `pose` показывается в админке как текущая позиция, подставляется при «Заменить на текущую
  позицию» для точки и при «Текущая поза ± допуск» в настройке стартовых зон.
- `run` — включены ли приводы; по нему админка рисует кнопку приводов.
- Остальные поля пульт игнорирует.

### 2.2. `behaviour.status` — от Behaviour

Содержимое пульт не разбирает. Любое сообщение — heartbeat Behaviour, тот же порог 2 с
(в опросе ПЛК `f3`).

### 2.3. `script.status` — от Behaviour

Пульт читает:

```json
{
  "running": false,
  "completed": true,
  "line": 12,
  "filename": "<имя скрипта>",
  "slot": "motion"
}
```

- `filename` — по нему пульт понимает, что это статус скрипта, который он запустил.
- `slot`: `"motion"` или `"search"`. Статусы `search` пульт игнорирует для отчёта ПЛК и конца init/main.
- `running: true` — скрипт идёт (в опросе ПЛК `f4 = 1`, только для motion).
- `running: false` после `running: true` — скрипт закончился, пульт шлёт ПЛК отчёт `7 7 R S`
  (`R`: 1 — init, 2 — основной; `S` = `completed`):
  - init-скрипт → задача «Робот готов» в предподготовке выполнена или в ошибке;
  - основной скрипт → время цикла; перезапускать ли, пульт решает по свежему кадру ПЛК.
- Статусы о конце, пришедшие раньше, чем `exec` ушёл в NATS, относятся к прошлому запуску
  того же файла и пропускаются.
- `line` пульт не использует.

## 3. KV (JetStream Key-Value)

### 3.1. Bucket `behaviour` — скрипты (только чтение)

Тот же bucket, что у веб-редактора скриптов. Ключ — `data.<имя скрипта>`, значение — JSON,
из которого пульт берёт только `code`:

```json
{
  "code": "<текст скрипта .chai>"
}
```

Если ключа нет или в записи нет строкового `code`, запуск не происходит, ошибка пишется в журнал,
ПЛК получает `7 7 R 0`.

Если bucket не открылся, NATS считается подключённым с предупреждением, но скрипты запустить
нельзя.

### 3.2. Bucket `robot_points` — точки робота (чтение и запись, только админка)

Ключ — имя точки в KV, значение — JSON точки. Координаты пульт ищет либо в корне, либо во
вложенном `data`, оси принимает строчными или заглавными, числом или строкой:

```json
{
  "name": "P1",
  "x": 100.0, "y": 50.0, "z": -20.0, "r": 0.0
}
```

```json
{
  "name": "P1",
  "data": {"X": 100.0, "Y": 50.0, "Z": -20.0, "R": 0.0}
}
```

- Чтение: все ключи bucket, сортировка по `name` (если `name` нет — по ключу).
- Запись («Заменить на текущую позицию»): пульт читает запись, меняет только `x/y/z/r`
  (и `X/Y/Z/R`, если они уже были) в корне и в `data`, остальные поля оставляет как есть,
  и кладёт обратно под тем же ключом.

## Сводка

| Subject / bucket | Направление | Сообщение | Где в пульте |
|---|---|---|---|
| `script.command` | → | `exec` | init по ячейке 60, основной по 56: 0 → 1 и перезапуск цикла |
| `motion.command` + `behaviour.command` + `script.command` | → | `stop` во все три | стоп во время init, стоп в цикле дольше таймаута, нет связи с ПЛК |
| `motion.command` | → | `stop` | админка |
| `motion.command` | → | `start` | админка |
| `motion.command` | → | `moveOffset` | админка |
| `motion.status` | ← | `pose`, `run` | heartbeat CTRL, стартовая зона для ПЛК, позиция в админке |
| `behaviour.status` | ← | любое | heartbeat Behaviour |
| `script.status` | ← | `running`, `completed`, `line`, `filename` | конец скрипта → `7 7 R S` на ПЛК |
| KV `behaviour` | чтение | `data.<имя>` → `code` | перед каждым `exec` |
| KV `robot_points` | чтение/запись | точки `x/y/z/r` | админка |
